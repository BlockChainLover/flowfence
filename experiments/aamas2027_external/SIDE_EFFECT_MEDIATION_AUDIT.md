RESEARCH_SIDE_EFFECT_MEDIATION: VERIFIED for registered-tool protected-runtime input paths in the deterministic/source audit.
DATABASE_SIDE_EFFECT_MEDIATION: VERIFIED for the same bounded registered-tool scope.

These are boundary coverage findings, not live service certification, scientific privacy success or complete environment certification. Context/state failures remain separate.

Research: all seven registered tools are invoked under both arms with deterministic arXiv/SemanticScholar/HTTP doubles. Their private-runtime input is the argument object; handlers do not access agent backing state or invoke a reachable generative helper. The common pre-dispatch argument boundary therefore precedes generated query/URL/author data reaching external services. Paper-return data is mediated at the result boundary. A protected outgoing URL is mediated before HTTP dispatch; sanitized requests retain the original tool capability. No per-tool semantic rule is added. Library-generated public retrieval processing is not a new protected-store origin; arbitrary secret reconstruction is outside the frozen exact-recognizer guarantee.

Database: only query_db is registered. Its generated SQL flows from the generic tool argument boundary to split_sql_statements and cursor.execute; clean query, backend SQL error and protected-query sanitization are exercised symmetrically. Startup SQL/Docker/anomaly commands use immutable original config before sidecar injection; termination uses a fixed command. Alerts/HTTP and helper diagnostics occur during initialization; their agent-tool registrations are commented out. This distinguishes modeled generated side effects from inactive source code. SQL/service behavior is doubled, not executed against live PostgreSQL/Docker. No SQL operation is removed or separately patched.

Coding: only create_solution and give_advice_and_revise are registered. Both publish solution.py; reviewer also reads and writes advices.json. One genuine builtins.open boundary scoped to the shared workspace buffers the original synchronous w-mode artifact and releases it before publication; json.dump chunks are handled as one artifact. No handler-name list, source rewrite or tool removal. Protected coder/reviewer solution/advice fixtures are intercepted in both arms; successful clean new-file content and clean JSON chunk bytes are unchanged. Diagnostic advice_log intentionally retains private fixture text locally and is not a shared artifact or safe output. Tester/debugger/analyst are not registered; this pin does not execute generated code through those tools. They must not be silently enabled in a formal run based on this certificate.

The formal runner is not approved. In particular, external service access, independent provider adaptation, concurrent execution, new tools and source/task changes are not certified. The current architecture still fails pre-publication mutable state and trusted nested model identity; no environment becomes eligible from this side-effect-only finding.
