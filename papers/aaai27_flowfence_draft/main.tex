\title{FlowFence-Lite: Propagation-Aware Privacy Containment for Multi-Agent LLM Systems}

\begin{abstract}
Multi-agent LLM systems move private information through memory, shared workspaces, inter-agent messages, tool arguments, and final outputs. Privacy failures therefore arise not only when a final answer leaks, but when sensitive content propagates through runtime channels before containment can occur. We present FlowFence-Lite, an event-level runtime containment layer for text-first multi-agent systems. FlowFence-Lite intercepts information-moving events, scores risk using policy, provenance, fanout, topology, and privilege signals, and applies policy-aware safe-view rewriting or quarantine before content enters broadly readable state. We evaluate the method using committed high-level evidence from an adapted AgentPoison retrieval-memory comparator, deterministic synthetic multi-agent benchmarks, a MiniMax-backed multi-agent synthetic-runtime coverage experiment, and held-out non-oracle validation. In the canonical 252-run MiniMax-only P1 MAS coverage over the synthetic deterministic runtime, FlowFence-Lite is clean across all 63 configured FlowFence runs, with task success 1.0 and zero raw/external leakage. A separate validation removes oracle attack annotations: deterministic held-out validation completes 540/540 runs and targeted MiniMax-backed synthetic-runtime validation completes 72/72 runs, with the non-oracle FlowFence variant again clean and zero oracle-annotation violations. These results support scoped containment claims for configured MiniMax-backed and deterministic synthetic-runtime settings. They do not support non-MiniMax generalization, production safety, real browser/desktop computer-use deployment, or arbitrary attack robustness.
\end{abstract}
