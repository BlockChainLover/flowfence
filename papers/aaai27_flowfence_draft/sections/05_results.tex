\paragraph{P0 retrieval-memory containment.}
Table~\ref{tab:p0_agentpoison} shows that no defense creates poisoned-retrieval exposure and non-zero attack manifestation on the adapted AgentPoison comparator. FlowFence-Lite quarantine with canonical action writeback reduces exposed poisoned retrieval and attack manifestation to zero on the saved P0 axis while raw poisoned retrieval remains internally present. This distinction matters: the method is not claiming that poisoned content never enters the runtime, but that it is contained before model-visible exposure and behavioral manifestation in this adapted setting. The static keyword row is an important caveat because a known-trigger same-axis filter is also strong here.

\paragraph{Topology and propagation.}
The strengthened deterministic MAS benchmark records topology-dependent propagation and shows FlowFence-Lite improving over prompt filtering on indirect synthetic attacks. This supports the mechanism intuition: leakage risk is not a scalar property of an output, but a function of where the content is written, how many agents can read it, and whether the path crosses principal or privilege boundaries. The claim remains deterministic synthetic evidence.

\paragraph{MiniMax-backed coverage.}
Table~\ref{tab:minimax_3seed} is the canonical MiniMax table. The MiniMax-only P1 MAS coverage over the synthetic deterministic runtime completed 252/252 configured runs after retrying one transient timeout. The aggregate coverage metrics across all defenses and attacks are task success 0.964286, unauthorized raw leakage mean 2.829365, external leakage mean 0.325397, cascade size mean 4.178571, and privilege reach mean 2.678571. Within that matrix, the FlowFence subset is clean across 63/63 configured FlowFence runs, with task success 1.0 and raw/external leakage 0.0.

The comparison counts show why this is a containment result rather than only a clean-subset statement. FlowFence improves or ties no defense, static ACL, and prompt filtering on configured raw/external leakage comparisons. Against no defense, FlowFence improves raw leakage in 42 groups and external leakage in 32 groups, tying the rest. Against static ACL, it improves raw leakage in 42 groups and external leakage in 30 groups. Against prompt filtering, it improves raw leakage in 18 groups and external leakage in 13 groups. The coverage also records \texttt{topology\_effect\_observed=true}.

\paragraph{Seed stability.}
Table~\ref{tab:seed_stability} records seed-level stability. Across seeds 1, 2, and 3, each seed has 21/21 clean FlowFence runs with task success 1.0 and zero raw/external leakage. This reduces the risk that the FlowFence clean subset is a single-seed artifact, but it does not establish robustness beyond the configured seeds. The aggregate seed rows also explain why cascade size need not be zero for a defended run: benign workflow events still occur, and contaminated or policy-relevant events can be present internally while raw and external leakage remain contained.

\paragraph{Non-oracle held-out validation.}
Table~\ref{tab:nonoracle} addresses the oracle-annotation concern. The earlier default engineering path used attack annotation as part of a poison signal. The paper-facing non-oracle variant removes that signal. Deterministic non-oracle validation completed 540/540 runs with no failures; \texttt{flowfence\_lite\_nonoracle} had task success 1.0, raw leakage 0.0, external leakage 0.0, and zero oracle-annotation violations. The targeted MiniMax-backed synthetic-runtime validation completed 72/72 runs with the same clean non-oracle FlowFence subset. The non-oracle variant improves or ties no defense, static ACL, and prompt filtering on configured held-out raw/external leakage comparisons. This substantially mitigates the oracle-annotation concern for the configured held-out matrices.

\paragraph{Mechanism ablation.}
The no-semantic-pattern ablation tied the full non-oracle variant on external leakage and task success but had higher raw leakage in deterministic results. This suggests semantic pattern detection contributes to raw-leakage containment, while policy, fanout, and safe-view mechanisms still matter. It does not prove that semantic detection is unnecessary.
