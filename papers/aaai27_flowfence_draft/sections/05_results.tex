
\section{Results}

\paragraph{RQ1: retrieval-memory containment.}
Table~\ref{tab:p0_agentpoison} reports the adapted AgentPoison retrieval-memory comparator. Without defense, the saved P0 axis exhibits poisoned-retrieval exposure and non-zero attack manifestation. FlowFence-Lite does not prevent poisoned content from being retrieved internally; rather, it quarantines or rewrites the retrieved content before it is exposed or acted on. This distinction matters: the containment target is not eliminating every contaminated input, but preventing it from becoming model-visible unsafe context or external leakage. Static keyword filtering is a strong weak baseline on known-trigger same-axis settings, which is why we do not use P0 alone to claim broad robustness.

\paragraph{RQ2: deterministic propagation.}
The deterministic MAS benchmark establishes that privacy risk depends on the runtime path, not only on text. After benchmark strengthening, topology effects appear: shared workspace / blackboard pathways create broader contaminated reach than linear handoff. This supports the paper's central framing that multi-agent privacy is a propagation problem. The deterministic evidence is not real-provider evidence; it validates the runtime mechanism and metric suite.

\paragraph{RQ3: MiniMax-backed coverage.}
Table~\ref{tab:minimax_3seed} is the canonical MiniMax result. The 252-run MiniMax-only coverage completed after retrying one transient timeout. FlowFence-Lite is clean across all 63 configured FlowFence runs, with task success 1.0 and zero raw/external leakage. Against no defense, FlowFence improves raw leakage in 42 groups and ties in 21; it improves external leakage in 32 groups and ties in 31. Against static ACL, it improves raw leakage in 42 groups and external leakage in 30 groups. Against prompt filtering, it improves raw leakage in 18 groups and external leakage in 13 groups, tying the remaining configured groups and never underperforming.

\input{tables/table_minimax_3seed}

Ties should not be read as failures. Many ties occur in no-attack or low-pressure settings where neither method leaks raw content. Improvement counts are most informative in attack-positive settings. Conversely, FlowFence's cascade size need not be zero: a contaminated seed may be observed and quarantined. The more important privacy outcome is that the FlowFence subset has zero unauthorized raw leakage, zero external leakage, and zero privilege reach in the committed coverage.

\paragraph{RQ4: topology and seed stability.}
The MiniMax coverage records \texttt{topology\_effect\_observed=true}; deterministic runs show the same qualitative direction. Blackboard/shared-workspace settings are riskier because one poisoned artifact can be read by multiple agents. Table~\ref{tab:seed_stability} shows that FlowFence is clean on seeds 1, 2, and 3. This does not prove non-MiniMax or production robustness, but it reduces the chance that the main result is a one-seed artifact.

\paragraph{RQ5: comparison with simple baselines.}
No defense exposes expected unprotected risk. Static ACL blocks some hard forbidden movements but cannot govern internal shared-state propagation. Prompt filtering handles obvious direct instructions better than no defense, but it fails on indirect and paraphrased workspace/summary attacks. FlowFence-Lite improves or ties the baselines on configured raw/external leakage comparisons while preserving task success in its own subset.

\paragraph{RQ6: non-oracle held-out validation.}
Table~\ref{tab:nonoracle} addresses the internal-validity concern that an earlier engineering path used oracle attack annotations. The non-oracle variant ignores \texttt{attack\_annotation.applied}, \texttt{attack\_id}, \texttt{attack\_mode}, and oracle labels. Deterministic non-oracle validation completes 540/540 runs with task success 1.0, zero raw/external leakage, and zero oracle-annotation violations. Targeted MiniMax-backed held-out validation completes 72/72 runs with the same clean outcome. This substantially mitigates the oracle-annotation and fixed-phrase concerns for the configured held-out paraphrase matrices.

\paragraph{RQ7: mechanism ablation.}
Table~\ref{tab:nonoracle} also reports the no-semantic-pattern ablation. Removing semantic request patterns keeps external leakage and task success tied in the deterministic evidence, but increases raw leakage relative to the non-oracle full variant. This suggests semantic pattern detection contributes to raw-leakage containment, while policy, fanout, safe-view, and quarantine mechanisms still matter. It does not prove that semantic detection is unnecessary, nor does it fully isolate every module.
