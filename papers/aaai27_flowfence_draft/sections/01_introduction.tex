\section{Introduction}

LLM agents are increasingly organized as systems: planners delegate to specialized workers, workers write shared notes, retrieval memory is replayed across turns, and tools carry information into external environments. These mechanisms make agents useful, but they also change the privacy problem. Sensitive content can leak before a final response is produced. A private budget, incident rationale, customer reference, or credential-like marker can be copied into a shared workspace, summarized into a handoff, passed to a low-trust agent, or placed in a tool argument. Output-only safety checks see only the last channel; multi-agent privacy failures often happen earlier.

We study this setting as a propagation and containment problem. The research gap is that many agent defenses focus on prompt-level filtering or final-output refusal, while multi-agent runtimes need to reason about how information moves through memory, workspaces, messages, and tools. The relevant measurement is therefore not only ``did the final answer leak?'' but also ``which event carried the sensitive content, how far did it propagate, and did it cross a policy boundary?''

FlowFence-Lite is a lightweight runtime containment layer for text-first multi-agent systems. It intercepts information-moving events, assigns risk using runtime-observable signals, and either allows the event, rewrites it into a policy-safe view, downgrades its lease, blocks it, or quarantines it before it becomes broadly readable state. The design is intentionally pragmatic: it does not require changing the base model, training a graph-risk scorer, or trusting ground-truth attack annotations at run time.

The empirical story is deliberately evidence-bound. We use four evidence layers: an adapted AgentPoison full-ReAct retrieval-memory comparator, deterministic synthetic multi-agent propagation benchmarks, a MiniMax-backed multi-agent synthetic-runtime coverage experiment, and non-oracle held-out validation. MiniMax is the only real provider represented. The P1 runtime is synthetic deterministic MAS with MiniMax final-writer calls where provider calls are enabled. We do not claim non-MiniMax generalization, production safety, real browser/desktop computer-use deployment, or arbitrary attack robustness.

This paper makes four contributions.
\begin{itemize}
    \item We formulate multi-agent privacy leakage as event-level propagation across messages, memory, workspaces, tools, and final outputs, with metrics for raw leakage, external leakage, cascade size, privilege reach, topology effects, and oracle-annotation violations.
    \item We introduce FlowFence-Lite, a runtime containment layer that combines policy-aware safe views, quarantine, privilege/lease signals, and topology/fanout features.
    \item We assemble a scoped benchmark suite covering adapted retrieval-memory poisoning, deterministic multi-agent propagation, MiniMax-backed synthetic-runtime coverage, and non-oracle held-out attacks.
    \item We report conservative empirical findings: in a 252-run MiniMax-only P1 MAS coverage over the synthetic deterministic runtime, FlowFence-Lite is clean across 63/63 configured FlowFence runs; in non-oracle held-out validation, the non-oracle variant remains clean in both deterministic and targeted MiniMax-backed synthetic-runtime settings.
\end{itemize}
