
\section{FlowFence-Lite}

FlowFence-Lite is a runtime containment layer, not a replacement for the base model. It mediates information-moving events before they update shared state or reach an external channel. Given an event, policy state, topology metadata, and lease/privilege context, the guard returns one of five decisions: allow, rewrite to a safe view, quarantine, block, or downgrade a lease.

\paragraph{Event-level pipeline.}
Figure~\ref{fig:flowfence_pipeline} summarizes the pipeline. Agents emit messages, memory writes, workspace writes, tool calls, and final outputs. FlowFence-Lite intercepts these events, computes risk from observable runtime context, applies the selected containment action, and logs the mediated event into a propagation graph. The unit of mediation is therefore the information movement itself, not only the final answer.

\paragraph{Risk scoring.}
For event $e$, FlowFence-Lite computes a bounded score
\[
    r(e) = \min\left(1, \sum_i w_i f_i(e)\right),
\]
where each $f_i(e)$ is a Boolean or real-valued runtime feature. Table~\ref{tab:risk_signals} lists the feature families. The scorer is deliberately inspectable: it uses raw-secret presence, forbidden channels, unauthorized recipients, cross-principal movement, shared-artifact fanout, low-trust to high-privilege movement, and instruction-like or sensitive-detail requests. The paper-facing non-oracle method does not use ground-truth attack labels, attack identifiers, or attack modes.

\paragraph{Safe-view rewriting.}
When a task needs context but policy forbids raw disclosure, FlowFence-Lite replaces raw sensitive values with coarse policy-approved abstractions. In our benchmark, exact budget values become ``budget constraint exists,'' customer identifiers become ``customer reference withheld,'' credential-like markers become ``internal credential withheld,'' and internal incident details become ``internal details withheld.'' The rewrite is intentionally simple and policy-driven. It is a containment primitive, not a second reasoning model.

\paragraph{Quarantine and lease signals.}
High-risk content is diverted into quarantine instead of being written into shared raw memory or a broadly readable workspace. Lease and privilege signals record when a channel should be narrowed or revoked, for example when low-trust content attempts to reach a high-privilege recipient. In the benchmark, these signals are deterministic metadata used for containment decisions and audit trails.

\paragraph{Non-oracle method.}
The final paper-facing method uses runtime-observable signals only. During implementation, we found that an earlier default path used an oracle attack annotation as part of a poison signal. We treat that path as an engineering risk that required validation, not as the method. The evaluated non-oracle variant ignores the attack-applied flag, attack identifiers, attack modes, and oracle labels; its decision metadata records that no oracle annotation was used.

\paragraph{Proposition 1: policy-preserving safe-view invariant.}
Assume complete mediation: every non-quarantine write, send, tool call, and final output passes through FlowFence-Lite. Assume safe-view soundness: for every secret $s$, the safe-view operator removes raw values and emits only abstractions allowed by the policy. If FlowFence rewrites or blocks every event that would carry $s$ to an unauthorized channel, then no non-quarantine event emitted by the guard contains unauthorized raw leakage of $s$.

\emph{Proof sketch.} Consider the event sequence in order. Before any mediated event is emitted, the invariant is vacuous. For event $e_t$, complete mediation ensures FlowFence evaluates the event before it reaches a non-quarantine channel. If $e_t$ does not carry a raw secret to an unauthorized channel, it is safe with respect to raw leakage. If it does, the guard blocks it, quarantines it, or replaces it with a sound safe view. Thus every emitted non-quarantine event contains no unauthorized raw value. Induction over $t$ gives the invariant. This connects the zero raw-leakage results to complete mediation plus sound rewriting, rather than to final-output filtering alone.

\paragraph{Proposition 2: topology fanout amplification.}
Let a contaminated artifact $o$ be readable by $F(o)$ downstream agents at the next propagation step. Without containment, a single contaminated write to $o$ can induce up to $F(o)$ contaminated reads in that step. In a chain topology $F(o)\leq 1$ for local handoffs, whereas a blackboard-style shared artifact can have $F(o)=\Theta(|A|)$. Therefore, for the same poisoned payload, blackboard/shared-workspace topologies can increase cascade size faster than chain handoffs.

\emph{Proof sketch.} A contaminated write creates one contaminated artifact. Each reader of that artifact can generate a contaminated read event. The number of such read events is bounded by the artifact's fanout. A chain exposes the artifact to at most the next agent at a step; a blackboard exposes it to all agents that read shared workspace. This motivates fanout and destination-zone features in the risk score and matches the topology effects observed in our synthetic-runtime benchmark.
